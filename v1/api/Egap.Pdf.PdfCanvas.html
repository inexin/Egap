An Egami canvas that draws onto a PDF page: the same drawing code that fills a raster writes PDF operators here (Phase 3, hub Q10). Paths, strokes, clips, opacity and blend modes become vector content; what PDF cannot express is drawn into an image at FallbackDpi and placed instead, with a warning.

Remarks

By default the canvas is in points, y down, from the top left of the page's crop box with the page's /Rotate applied, so it draws what a viewer shows; Pdf draws in PDF's own space instead. The drawing goes over or under the page's existing content without touching it (Phase 3 design Q5), and is written when the canvas is disposed.

PDF can only multiply the current transformation matrix, so a canvas transform is written lazily: drawing calls that share a transform are written together inside q, the transform's cm and Q. Clips are written in device space at the level of their Egami.Drawing.Canvas.Save(), so Egami.Drawing.Canvas.Restore() undoes them as PDF's Q does.

OnDrawMesh(Mesh, Paint, BlendMode, ReadOnlySpan<GradientStop>)

Draws a mesh with at least one triangle; a mesh with values comes with stops. A PDF backend can write it as a free-form or lattice-form shading (types 4 and 5).
