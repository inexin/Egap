A document's pages in order, numbered from 0 (Phase 2 Q2). The list is built on first use by walking the page tree from the catalog; only the tree's nodes are loaded, not the pages' content. A broken tree is repaired in memory with MalformedPageTree warnings, as pdf.js and PDFium read it.

Remarks

Edits through this collection change the page tree in place (Phase 2 Q3): only the page, the node that lists it and the /Count of the nodes above are written, so an incremental save stays small; a node is split once it passes 128 kids. A tree too broken to edit in place (loops, pages or nodes listed twice, no tree at all) is rebuilt before the first edit, with a warning. A page tree changed by hand through its dictionaries is not seen again by this collection.

Import(PdfDocument, IEnumerable<int>?, int?, PdfImportOptions?)

Imports pages from another document (Phase 2 task 18): each page is copied with everything it reaches, its resources, content, annotations and what they use, but not the source's page tree; attributes it inherited there are written on the copy. Objects are copied once per source (Q4), so pages that share a font share the copy. References to source pages that are not imported become null. Streams are copied as the source holds them and read when this document is written, so source must stay open until then.

public IReadOnlyList<PdfPage> Import(PdfDocument source, IEnumerable<int>? pageIndices = null, int? at = null, PdfImportOptions? options = null)

Remarks

The pages bring what they need to keep working (Phase 2 Q5, Q6): their annotations; their form fields, the top-level ones renamed with a suffix and a warning when the name is taken; the named destinations their links use; the layers they use; and their page labels. The first import from a source also brings its attachments, renamed with a suffix when the name is taken, and its outline, appended at the top level without the items that lead to pages not imported. The structure tree and an XFA form stay behind, with a warning.
