OpenDocument Text

Egap.Documents reads OpenDocument Text, the format LibreOffice and OpenOffice write and Word opens: ODT documents, OTT templates and flat FODT files, from ODF 1.2 to 1.4. It needs no add-on package. Writing ODT is not there yet; save a document read from ODT as DOCX, RTF, PDF or any other format Egap writes.

Reading

OdtFormat.Load reads a file or a stream. Document.Load and Document.Identify know ODT and OTT by the mimetype entry an OpenDocument package starts with, and FODT by its root element, so a file is found whatever its extension.

using Egap.Documents;

Document minutes = OdtFormat.Load("minutes.odt", out IReadOnlyList<ConversionWarning> warnings);
Document same = Document.Load("minutes.odt");                     // found by its mimetype entry
Document flat = OdtFormat.Load("minutes.fodt");                   // one XML file, pictures inline
minutes.SaveAsDocx("minutes.docx");

The reader follows the OpenDocument 1.3 specification and what LibreOffice writes. It reads:

  • The package: the mimetype entry, the manifest, the content, styles, meta and settings parts and the pictures, and the same parts in one flat XML file. Document information and custom properties come from the meta part.
  • Common styles as the model's styles, with their base and next style. A style LibreOffice names after one of Word's built-in styles gets Word's style id, such as Heading1 for "Heading 1" and Normal for "Default Paragraph Style". Automatic styles become direct formatting, and default styles the document defaults.
  • Character and paragraph formatting: fonts, sizes, colours, highlighting, underlines and strikes, raised and lowered text, spacing, scaling, caps, hidden text, languages, alignment, indents, spacing, line height, borders, shading, tab stops, keeping together and with the next paragraph, widows and orphans, and page and column breaks.
  • Lists from list styles, with each level's numbering, labels and indents; a new list restarts its numbers, and a list that continues another (text:continue-numbering, text:continue-list) goes on counting. Headings are numbered by the outline style.
  • Tables with their columns, header rows, cells spanning columns and rows, nested tables, borders, shading, padding and alignment.
  • Page styles as sections: each master page's size, orientation, margins, columns and page numbering, its headers and footers, and a different first page or left page. Sections with columns become continuous sections.
  • Footnotes and endnotes, comments with their ranges, authors, dates and whether they are resolved, bookmarks, and links.
  • Fields as Word's fields: page numbers and counts, dates and times, document information, file names, chapters, sequences, references to bookmarks, sequences and notes, custom properties and mail merge columns. A table of contents or other index is a TOC field holding its entries. Fields Word has nothing like, such as variables, keep their text.
  • Tracked insertions and deletions with their authors and dates, a deletion that spans paragraphs too. Tracked formatting changes are read as accepted, with a warning.
  • Frames: pictures (stored in the package or, in a flat file, inline), text boxes, rectangles, ellipses and lines, inline or floating, placed and wrapped as the frame says. A frame holding only a table, as LibreOffice writes Word's floating tables, is a floating table.

Charts, formulas and other embedded objects come in as islands that keep their markup and draw the picture the file holds for them; other drawing shapes and groups are islands too. Each of those is reported as a ConversionWarning, and so is a picture the package does not hold. Markup the reader does not know is kept in the document's extension data under the format name odt.

Password-protected files

Give the password in OdtLoadOptions.Password, or in DocumentLoadOptions.Password with Document.Load. A missing or wrong password throws a DocumentPasswordException, whose WrongPassword tells the two apart; PasswordCallback is asked for another password, with the attempt's number, until it gives a right one or null. Document.Identify reports an encrypted ODT as DocumentFormatKind.Encrypted, so a program can ask for the password first.

using Egap.Documents;

if (Document.Identify("report.odt") == DocumentFormatKind.Encrypted)
{
    Document report = Document.Load("report.odt", new DocumentLoadOptions { Password = "s3cret" });
}

Document asked = OdtFormat.Load("report.odt", new OdtLoadOptions
{
    PasswordCallback = attempt => attempt <= 3 ? Console.ReadLine() : null,
});

Egap reads every encryption LibreOffice writes:

Written by Encryption
LibreOffice 24.2 and later, by default The whole package in one file, AES-256 in GCM mode, the key from Argon2id
LibreOffice for ODF 1.2 to 1.4, other ODF writers Each file with AES-256 in CBC mode, the key from PBKDF2
OpenOffice.org, LibreOffice for ODF 1.0 and 1.1 Each file with Blowfish, the key from PBKDF2

A file whose key derivation asks for more work than any writer uses (more than 10,000,000 PBKDF2 iterations for one file or 20,000,000 for all, or Argon2id over more than 256 MiB) throws a DocumentLimitException instead of running for minutes.

Limits

An ODT package is read under DocumentLimits like DOCX: the number of entries, the size of each part and of all of them, the compression ratio and the nesting depth. Pass your own in OdtLoadOptions.Limits, or in DocumentLoadOptions.Limits with Document.Load; a file past a limit throws a DocumentLimitException.

using Egap.Documents;

Document upload = OdtFormat.Load("upload.odt", new OdtLoadOptions
{
    Limits = new DocumentLimits { MaxPartSize = 64 * 1024 * 1024 },
});
