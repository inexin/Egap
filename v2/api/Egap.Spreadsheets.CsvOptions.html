Properties

Culture

The culture numbers and dates are read and written in: 1.234,5 and 15.03.2024 in German. The invariant culture, the default, reads and writes them as Excel in English does.

public CultureInfo Culture { get; set; }

Property Value

CultureInfo

Exceptions

ArgumentNullException

The culture set is null.

DetectTypes

Whether reading turns fields into numbers, percentages, TRUE and FALSE, dates, times and errors, with a number format that shows them as written; when false, every field is text. A number with a leading zero, such as 007, stays text, and so does a field that starts with =: reading never makes formulas. Default true.

public bool DetectTypes { get; set; }

Property Value

bool

Encoding

The text encoding, or null for UTF-8. Reading honours a byte order mark over this setting; writing UTF-8 adds one, as Excel needs to tell UTF-8 from the system code page.

public Encoding? Encoding { get; set; }

Property Value

Encoding

NewLine

The line break written after each row. Default \r\n, as RFC 4180 has it.

public string NewLine { get; set; }

Property Value

string

Exceptions

ArgumentException

The line break set is not \r\n, \n or \r.

Separator

The field separator, or null to choose one: a sep= first line if the file has one, a tab for a .tsv or .tab path, otherwise whichever of comma, semicolon and tab the first line holds most of. Writing with null uses a tab for a .tsv or .tab path, otherwise the culture's list separator, as Excel does: a comma in English, a semicolon where the comma is the decimal separator.

public char? Separator { get; set; }

char?

WriteFormattedText

Whether writing shows each value as its cell shows it (Text), as Excel saves CSV; when false, numbers are written in full, in Culture, and dates as their serial numbers. Default true.

public bool WriteFormattedText { get; set; }
